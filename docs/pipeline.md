# Устройство пайплайна

Пайплайн описан в [`ci/github-actions-ci.yml`](../ci/github-actions-ci.yml) и запускается на каждый push и pull request.

## Стадии

```
push / PR ──► install ──► lint ──► test ──► docker build ──► (push образа)
               │           │        │            │
          pip install   flake8    pytest   docker build
```

| Стадия | Команда локально | Что ломает сборку |
|--------|------------------|-------------------|
| install | `make install` | несовместимые или недоступные версии зависимостей |
| lint | `make lint` | нарушения стиля и очевидные ошибки (`flake8`, настройки в `.flake8`) |
| test | `make test` | упавшие тесты `pytest` |
| docker build | `make docker-build` | ошибка в `Dockerfile` или отсутствующие файлы в контексте |
| smoke | `make smoke` | образ собирается, но приложение не запускается внутри контейнера |

Перед отправкой кода достаточно выполнить `make check` — это те же lint и test, что и в CI.

## Принципы

- **Быстрая обратная связь.** Дешёвые проверки (lint) идут раньше дорогих (сборка образа).
- **Одинаковый результат локально и в CI.** Все команды вынесены в `Makefile`, версии зависимостей зафиксированы в `requirements.txt`.
- **Минимальный контекст сборки.** `.dockerignore` исключает тесты, документацию и служебные каталоги из образа.
- **Автоматические обновления зависимостей.** `.github/dependabot.yml` раз в неделю предлагает обновления для pip и базового образа.

## Публикация образа

Шаг публикации в пайплайне — заглушка. Для настоящей публикации:

1. Создайте в настройках репозитория секреты `REGISTRY_USERNAME` и `REGISTRY_PASSWORD` (Settings → Secrets and variables → Actions).
2. Выполняйте вход в реестр через секреты, а не через значения в файле:
   ```yaml
   - uses: docker/login-action@v3
     with:
       registry: ghcr.io
       username: ${{ github.actor }}
       password: ${{ secrets.GITHUB_TOKEN }}
   ```
3. Публикуйте образ только из ветки `main`: `if: github.ref == 'refs/heads/main'`.

## Рекомендуемые защиты ветки `main`

- Требовать прохождения проверок CI перед слиянием.
- Запретить прямые push в `main` (только через pull request).
- Требовать актуальности ветки относительно `main`.
